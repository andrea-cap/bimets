# Stochastic simulation

[Back to the tutorial index](README.md)

`stochastic_simulate()` repeatedly solves the deterministic model after
perturbing endogenous add-factors or exogenous observations. The equivalent
methods are `model.stochastic_simulate()` and
`bound_model.stochastic_simulate()`. The exact BIMETS R name
`STOCHSIMULATE()` is also exported.

```python
from bimets import BimetsModel, StochasticDisturbance, stochastic_simulate, timeseries

stochastic_model = BimetsModel.from_text(
    """MODEL
IDENTITY> y
EQ> y = x
END""",
    name="stochastic-example",
)
stochastic_data = {
    "y": timeseries([0, 0, 0], start=(2000, 1)),
    "x": timeseries([10, 10, 10], start=(2000, 1)),
}

stochastic_result = stochastic_simulate(
    stochastic_model,
    stochastic_data,
    coefficients={},
    time_range=(2000, 1, 2002, 1),
    disturbances={
        # Add an exogenous uniform disturbance over the complete range.
        "x": StochasticDisturbance("UNIFORM", (-1, 1)),
        # Add a normal disturbance to the endogenous equation in 2001.
        "y": StochasticDisturbance(
            "NORMAL",
            (0, 0.5),
            time_range=(2001, 1, 2001, 1),
        ),
    },
    replicas=100,
    seed=123,
)

stochastic_result.baseline["y"]
stochastic_result["y"].mean
stochastic_result["y"].standard_deviation
stochastic_result["y"].sd       # BIMETS-compatible result-name alias
stochastic_result["y"].realizations.shape  # (3 periods, 100 replicas)
stochastic_result.summary()
```

The supported disturbance distributions correspond to the original
`StochStructure` types:

| Python distribution | BIMETS R type | Parameters and behavior |
|---|---|---|
| `NORMAL` | `NORM` | `(mean, standard_deviation)`; additive |
| `UNIFORM` | `UNIF` | `(lower, upper)`; additive |
| `MATRIX` | `MATRIX` | A `(periods, replicas)` NumPy array; additive for endogenous variables and replacing for exogenous variables |

`NORM` and `UNIF` are accepted as aliases. Omitting `time_range` applies a
disturbance over the complete simulation range, corresponding to `TSRANGE=TRUE`
in R. Disturbances remain i.i.d. when a behavioral equation declares
`ERROR> AUTO(n)`, consistently with the documented BIMETS behavior.

With an explicit `seed`, normal and uniform draws reproduce BIMETS R's default
Mersenne Twister, inversion-normal transformation, variable traversal, and
column-major matrix filling. With `seed=None`, Python deliberately uses an
independent NumPy generator.

The result keeps the unperturbed deterministic solution separate from the
perturbed matrices. `instrument_baseline` and `instrument_realizations`
contain, respectively, the original and perturbed exogenous values or
endogenous add-factors. Mean and sample standard deviation are calculated only
across perturbed realizations, as in BIMETS R. A single realization therefore
has an undefined (`NaN`) sample standard deviation.

The original advanced Klein example applies a normal disturbance to the `cn`
add-factor and a uniform disturbance to government expenditure `g`. Its Python
structure is expressed directly as:

```python
klein_disturbances = {
    "cn": StochasticDisturbance(
        "NORMAL",
        (0, consumption.standard_error),
        time_range=(1942, 1, 1942, 1),
    ),
    "g": StochasticDisturbance("UNIFORM", (-1, 1)),
}
```

Stochastic simulation works with both backward-looking and forward-looking
models and forwards Gauss-Seidel or Newton settings to every realization.
Gauss-Seidel evaluates the baseline and realizations as synchronized NumPy
columns with one convergence stop. With `algorithm="NEWTON"`, the unperturbed
baseline is simulated first and its sparse LU factorizations are frozen for
multi-right-hand-side updates of the perturbed columns. This applies to both
backward- and forward-looking systems. Column-specific relaxation handles a
slow common Jacobian. With `algorithm="FULLNEWTON"`, every replica instead
builds and adapts its own sparse Jacobian. This matches the functional
distinction in BIMETS R and is useful when large disturbances make the common
baseline Jacobian unsuitable.

Independent `FULLNEWTON` realizations may be distributed across processes:

```python
result = stochastic_simulate(
    model,
    data,
    coefficients=coefficients,
    time_range=(2025, 1, 2026, 4),
    disturbances=disturbances,
    replicas=100,
    algorithm="FULLNEWTON",
    workers=2,
)
```

`workers=1` remains the default. Process startup and serialization have a real
cost, so multiple workers are useful primarily for sufficiently expensive
replicas. `workers>1` is rejected for Gauss-Seidel and ordinary `NEWTON`:
those algorithms already solve synchronized columns in compiled NumPy/SciPy
kernels and, for Newton, reuse one baseline Jacobian.

`jacobian_drop` keeps excluded feedback variables in vectorized Gauss-Seidel
updates while Newton solves the reduced shared system. The hybrid convergence
check covers the complete feedback set, including forward-looking horizons.

Large sparse Newton right-hand-side matrices are solved in bounded column
blocks. Every block belongs to the same Newton iteration: convergence is still
tested once over the complete baseline-and-replica matrix, so memory reduction
does not alter BIMETS R's shared stopping semantics. The realization result
matrix itself remains allocated because it is part of the public result.

The `backfill` argument prepends historical values to `result.baseline`. Means,
standard deviations, and realization matrices retain the requested simulation
range, matching their interpretation as stochastic outputs.

signatures and result objects. The shared-column and multiprocessing backends
are explained in [Solver architecture and execution
