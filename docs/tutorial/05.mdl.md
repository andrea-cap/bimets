# Model Description Language

[Back to the tutorial index](README.md)

bimets can load, validate, and inspect models written in the BIMETS Model
Description Language (MDL). Supply a definition as text or as a UTF-8 file:

```python
from bimets import load_model, parse_mdl

model_text = """MODEL
IDENTITY> y
EQ> y = x
END"""

model = load_model(model_text=model_text, name="example")
same_model = parse_mdl(model_text, name="example")

# A UTF-8 MDL file is an alternative to model_text:
# file_model = load_model(model_file="model.mdl")
```

Both functions return an immutable `BimetsModel`. MDL expressions are parsed
into a public, typed expression tree; model text is never passed to Python
`eval()`.

`LOAD_MODEL` and `LOAD_MODEL_DATA` are uppercase compatibility aliases for
`load_model` and `bind_model_data`. The modeling operations similarly expose
`ESTIMATE`, `SIMULATE`, `STOCHSIMULATE`, `MULTMATRIX`, `RENORM`, and `OPTIMIZE`.
They retain Python signatures and immutable return values; model and
bound-model methods use the same semantics.

## Klein model example

The following definition is based on the Klein Model 1 example distributed
with the original BIMETS package:

```python
from bimets import load_model

klein_definition = """MODEL

COMMENT> Consumption
BEHAVIORAL> cn
TSRANGE 1921 1 1941 1
EQ> cn = a1 + a2*p + a3*TSLAG(p,1) + a4*(w1+w2)
COEFF> a1 a2 a3 a4

COMMENT> Investment
BEHAVIORAL> i
TSRANGE 1921 1 1941 1
EQ> i = b1 + b2*p + b3*TSLAG(p,1) + b4*TSLAG(k,1)
COEFF> b1 b2 b3 b4

COMMENT> Demand for Labor
BEHAVIORAL> w1
TSRANGE 1921 1 1941 1
EQ> w1 = c1 + c2*(y+t-w2) + c3*TSLAG(y+t-w2,1) + c4*time
COEFF> c1 c2 c3 c4

COMMENT> Gross National Product
IDENTITY> y
EQ> y = cn + i + g - t

COMMENT> Profits
IDENTITY> p
EQ> p = y - (w1+w2)

COMMENT> Capital Stock
IDENTITY> k
EQ> k = TSLAG(k,1) + i

END"""

klein = load_model(model_text=klein_definition, name="klein")

klein.endogenous
# ('cn', 'i', 'w1', 'y', 'p', 'k')

klein.exogenous
# ('g', 't', 'time', 'w2')

klein.coefficient_count  # 12
klein.max_lag            # 1
klein.forward_looking    # False

consumption = klein.behavioral("cn")
consumption.coefficients
# ('a1', 'a2', 'a3', 'a4')

capital = klein.identity("k")
capital.alternatives[0].equation
```

`dependencies` exposes current-period dependencies between endogenous
variables. The simulation layer uses this information to build the incidence
graph, order recursive components, and identify simultaneous blocks:

```python
klein.dependencies["y"]   # frozenset({'cn', 'i'})
klein.dependencies["k"]   # frozenset({'i'}); TSLAG(k,1) is not current-period
```

## Supported MDL syntax

The parser currently supports:

- `MODEL` and `END` document boundaries;
- `BEHAVIORAL>` and its `EQUATION>` alias;
- `IDENTITY>`, including repeated conditional definitions;
- `TSRANGE`, `EQ>`, `COEFF>`, `ERROR> AUTO(n)`, `RESTRICT>`, `PDL>`,
  `IV>`, `IF>`, `COMMENT>`, and `$` line comments;
- arithmetic, comparison, and logical MDL expressions;
- `TSLAG`, `TSLEAD`, `TSDELTA`, `TSDELTAP`, `TSDELTALOG`, `MOVAVG`,
  `MOVSUM`, `LOG`, `EXP`, and `ABS`;
- the historical aliases `LAG`, `LEAD`, `DEL`, `MAVE`, and `MTOT`;
- the identity, `LOG`, `EXP`, `TSDELTA`, `TSDELTAP`, and `TSDELTALOG`
  transformations on the left-hand side of an equation;
- discovery of endogenous and exogenous variables, maximum lag and lead, and
  current-period dependencies.

Parsed declarations have dedicated public types such as
`BehavioralEquation`, `IdentityEquation`, `MdlEquation`, `MdlTimeRange`,
`PdlDefinition`, and `CoefficientRestriction`. Invalid input raises
`MdlSyntaxError`, including the source line when available.

Every variable declared by an `IDENTITY>` or `BEHAVIORAL>` group is classified
as endogenous before simulation. This also applies to conditional identities:

```python
model.endogenous
model.conditional_endogenous
```

`conditional_endogenous` identifies the subset containing at least one `IF>`.
Conditions are not simplified while loading the model because their values may
depend on endogenous variables and may change during convergence.

## Implemented scope and intentional exclusions

The MDL layer covers definition, parsing, semantic validation, static
inspection, safe expression evaluation, and model-data binding. The modeling
APIs then support OLS and IV estimation, linear restrictions, Almon PDLs,
autoregressive errors, Chow stability analysis, backward- and forward-looking
simulation, stochastic simulation, multiplier matrices, endogenous targeting,
and Monte Carlo optimal control.

Newton simulation uses structurally colored sparse Jacobians. `backfill` and
`jacobian_drop` are available throughout the simulation APIs. As in BIMETS R,
`FULLNEWTON` is not accepted by a single deterministic `simulate()` call; it
is available for stochastic simulation, multiplier matrices, renormalization,
and optimization, where each realization or shocked solution owns its
Jacobian.

The remaining exclusions are intentional interface or presentation choices:

- the mutable data-loading behavior of `LOAD_MODEL_DATA`; Python instead
  creates an immutable `BoundModel` with `model.bind(data)`;
- the original simulation reporting and plotting facilities.

Legacy `STORE>` declarations are accepted with the same shape as BIMETS R:

```text
STORE> archive_slot(2)
```

The variable name and non-negative integer position are validated, after which
the declaration is discarded and has no effect on estimation or simulation.
This differs from the R implementation, which retains the parsed values as
`storeVarName` and `storePosition` in its mutable behavioral-equation object,
even though its current modeling procedures do not consume them. The Python
port avoids exposing unused state in its public immutable model API.

As in the original syntax, a space before the angle bracket is accepted by
every angle-bracket directive, so `STORE >`, `EQ >`, and `IDENTITY >` are
equivalent to their compact forms.

The legacy `oldStyleModel` input mode, in which operational lines could carry
an additional leading `$`, is not ported either. Standard `$` comment lines
remain supported. Generated R implementation details such as `eqSimExp`,
`eqSimExpText`, and mutable nested model lists are replaced by the typed MDL
expression tree and immutable model objects.

Unknown directives are rejected as well. This is deliberately stricter than
the original string-based parser, which can silently ignore an unknown line
in some positions.

See the [MDL API reference](../reference/mdl.md) for the complete public
expression and model types, and [Key differences from BIMETS
R](../explanation/migration-from-r.md) for the representation and execution
choices made by the Python port.
