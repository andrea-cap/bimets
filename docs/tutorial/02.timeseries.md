# Time-series guide

[Back to the tutorial index](README.md)

This guide presents the time-series workflow, from construction and
calendar-aware indexing to conversion, display, datasets, and CSV exchange.
For a shorter workflow built around one dataset, see
[Manipulating time series](03.manipulating-timeseries.md). Exact signatures
and return types are listed in the [time-series API
reference](../reference/timeseries.md).

## Creating a time series

The recommended way to create a series is the `timeseries()` function:

```python
from bimets import timeseries

gdp = timeseries(
    [100.0, 102.0, 105.0, 107.0],
    start=(2020, 1),
    freq="Q",
    title="GDP",
    units="index",
    source="Example",
)
```

`timeseries()` returns a `BimetsSeries`. It is the user-oriented
constructor and directly accepts the most common metadata fields: `title`,
`units`, `source`, and `scale_factor`.

For code being translated from BIMETS R, `TIMESERIES` and `TSERIES` are aliases
of the same constructor. Compatible R function names are available with their
original case-sensitive spelling:

```python
from bimets import MOVAVG, TIMESERIES, TSLAG

series = TIMESERIES([1, 2, 3], start=(2020, 1), freq="Q")
lagged = TSLAG(series, periods=1)
average = MOVAVG(series, window=2)
```

The aliases use Python argument names; methods and the canonical lowercase API
are unchanged.

`BimetsSeries` is the public type representing a series. It is useful for type
annotations, `isinstance()` checks, and advanced construction with a metadata
dictionary:

```python
from bimets import BimetsSeries

def growth(series: BimetsSeries) -> BimetsSeries:
    return series.delta_percent()

advanced_series = BimetsSeries(
    [1, 2, 3],
    start=(2020, 1),
    freq="Y",
    metadata={"provider_id": 42},
)
```

In normal application code, create series with `timeseries()` and use
`BimetsSeries` in annotations and type checks.

### Frequencies

The frequency can be specified with an alias or with the number of periods per
year:

| Series | Alias | Frequency |
|---|---:|---:|
| Yearly | `"Y"` or `"A"` | `1` |
| Semiannual | `"S"` | `2` |
| Three periods per year | — | `3` |
| Quarterly | `"Q"` | `4` |
| Monthly | `"M"` | `12` |
| Two periods per month | — | `24` |
| Three periods per month | — | `36` |
| Weekly | `"W"` | `53` |
| Daily | `"D"` | `366` |

The `start=(year, period)` index uses one-based periods. For example,
`(2020, 3)` denotes the third quarter in a quarterly series and the third month
in a monthly series.

## Accessing and indexing a series

A `BimetsSeries` has two related index systems:

- Python positions are zero-based and are used with square brackets;
- calendar periods use a year and a one-based period within the year.

Keeping the two forms explicit avoids ambiguity between, for example,
position `1` and the first quarter of a year.

### Positional access and slicing

```python
series = timeseries([10, 20, 30, 40], start=(2020, 3), freq="Q")

series.start                 # YearPeriod(year=2020, period=3)
series.end                   # YearPeriod(year=2021, period=2)
series.freq                  # Frequency.QUARTERLY
series.values                # array([10., 20., 30., 40.])
series.metadata              # associated metadata

series[0]       # 10.0: first observation
series[-1]      # 40.0: last observation

middle = series[1:3]
middle.values   # array([20., 30.])
middle.start    # YearPeriod(year=2020, period=4)
middle.end      # YearPeriod(year=2021, period=1)
```

Slices follow normal Python rules: the start is included and the stop is
excluded. They return a new series with the calendar shifted to its first
selected observation. Slice steps such as `series[::2]` and empty slices are
not supported because a `BimetsSeries` must remain non-empty and regularly
spaced.

Iteration and `len()` also use observation positions:

```python
len(series)       # 4
list(series)      # [10.0, 20.0, 30.0, 40.0]
```

### Year-period access

Use `at_period()` to retrieve a value from its calendar index and
`period_at()` for the inverse mapping:

```python
series.at_period(2020, 4)  # 20.0
series.at_period(2021, 1)  # 30.0

series.period_at(0)        # YearPeriod(year=2020, period=3)
series.period_at(2)        # YearPeriod(year=2021, period=1)
series.period_at(-1)       # YearPeriod(year=2021, period=2)
```

The `period` argument is one-based. An access outside the stored range raises
`IndexError`. The equivalent BIMETS R-style read syntax is also supported:

```python
series[[2020, 4]]  # 20.0

start = [2020, 4]
end = [2021, 1]

series[[start]]              # 20.0
selection = series[[start, end]]
selection.values             # array([20., 30.])

# The same inclusive range, written inline
same_selection = series[[[2020, 4], [2021, 1]]]
```

The nested list mirrors R's double-square-bracket operator. A flat
`[year, period]` or a list containing one period pair selects one observation;
two period pairs select an inclusive range. Years and periods must be positive
integers. A range partially outside the series is clipped to its overlap; a
range with no overlap raises `ValueError`.

Direct assignment such as `series[[2020, 4]] = 25` is not supported because
`BimetsSeries` is immutable. `with_values()` provides the corresponding
operation and returns a new series:

```python
updated = series.with_values([2020, 4], 25)
ranged = series.with_values([[2020, 4], [2021, 1]], [25, 30])

series[[2020, 4]]   # 20.0: unchanged
updated[[2020, 4]]  # 25.0
```

A scalar is broadcast over an inclusive range. A sequence assigned at one
year-period continues from that period and can extend the series, matching the
original `ts[[year, period]] <- c(...)` behavior:

```python
extended = series.with_values([2021, 3], [50, 60])
extended.end          # YearPeriod(year=2021, period=4)
extended.values       # array([10., 20., 30., 40., 50., 60.])
```

Extension is enabled by default and fills any gap with `numpy.nan`. Pass
`extend=False` to reject updates outside the existing range. The explicit
`at_period()` and `project()` methods remain available for code that favors
conventional Python APIs.

Use `project()` when selecting an inclusive period range:

```python
selection = series.project(start=(2020, 4), end=(2021, 1))
selection.values  # array([20., 30.])
```

Unlike a Python slice, both `project()` bounds are included. By default the
requested range is clipped to the available observations. With `extend=True`,
periods outside the source range are retained and filled with `numpy.nan`.

### Calendar-date access

Dates are converted to the period that contains them. BIMETS-compatible ISO
date selectors work directly with `[]`:

```python
series["2020-11"]          # 20.0
series["2020"]             # all available observations in 2020
series["2020-08/2021-03"]  # inclusive closed range
series["2020-08/"]         # from August 2020 to the series end
series["/2021-03"]         # from the series start through March 2021
```

`YYYY-MM` and `YYYY-MM-DD` select the containing period, while `YYYY` selects
that calendar year. Closed and open ranges are clipped to the observations
available in the series. A `datetime.date` can also select one observation.

Individual access and inclusive range selection are additionally available as
methods:

```python
from datetime import date

series.at_date(date(2020, 11, 15))  # 20.0, from 2020 Q4

dated = series.between_dates(
    date(2020, 8, 1),
    date(2021, 3, 1),
)
dated.values  # array([10., 20., 30.])
```

Date selections use the same immutable update API:

```python
revised = series.with_values("2020-08/2021-03", 99)
revised["2020-11"]  # 99.0
```

Calendar helpers expose the same mappings directly:

```python
from bimets import date_to_year_period, get_dates, year_period_to_date

period = date_to_year_period(date(2020, 5, 20), "Q")
period_end = year_period_to_date(period, "Q")
all_dates = get_dates(series)
same_dates = series.dates()
```

`get_dates()` uses the last date in each period by default. Pass
`date_in_period="first"` to use period starts or `format="%Y-%m-%d"` to return
formatted strings.

### Values, datasets, and masks

`series.values` provides a read-only NumPy array. Make an explicit copy before
changing values outside bimets:

```python
editable_values = series.values.copy()
editable_values[0] = 99
```

Series themselves are immutable: transformations and slices return new
objects. A `BimetsDataset` is indexed by series name, while its contained
series still use the rules above:

```python
from bimets import BimetsDataset

data = BimetsDataset({"gdp": series})
data["gdp"]                 # the BimetsSeries
data["gdp"].at_period(2021, 1)  # 30.0
```

Comparison results are `BimetsMask` objects. Masks support positional access
and slicing, but they are logical results rather than implicit selectors for
a `BimetsSeries`:

```python
high = series >= 30
high[0]       # False
list(high)    # [False, False, True, True]
```

## Arithmetic, comparisons, and masks

Standard Python operators work with numeric scalars and with another
`BimetsSeries`:

```python
real_gdp = gdp / 1.03
indexed_gdp = 100 * gdp / gdp[0]

other = timeseries([101, 103, 106], start=(2020, 2), freq="Q")
combined = gdp + other
```

Two series must have the same frequency. They are automatically aligned on
the intersection of their ranges, so `combined` starts at the latest of the
two start periods and ends at the earliest end period. An empty intersection
raises `ValueError`. Arithmetic results do not inherit descriptive metadata,
which avoids attaching metadata from only one operand to a derived series.

The supported arithmetic operators are `+`, `-`, `*`, `/`, `//`, `%`, and
`**`, including their scalar-on-the-left forms. Unary `+`, unary `-`, and
`abs()` are also available.

Comparisons produce a `BimetsMask`, not a plain NumPy array:

```python
from bimets import BimetsMask

high_growth = gdp > 105
stable = (gdp >= 100) & (gdp <= 110)

high_growth.values       # True, False, or None for each period
high_growth.any()
stable.all()
```

`BimetsMask` preserves the range and frequency of the comparison. Missing
numeric observations become `None`, providing the same three-valued meaning
as R logical series with `NA`. Masks support `&`, `|`, `^`, and `~`; use
`any()` or `all()` rather than converting a multi-period mask to `bool`.

## Lag, lead, and differences

Most single-series operations are available both as methods and as functions:

```python
from bimets import tsdelta, tsdeltalog, tsdeltap, tslag, tslead

lagged = tslag(gdp, 1)
led = tslead(gdp, 1)
difference = tsdelta(gdp, lag=1)
log_difference = tsdeltalog(gdp, lag=1)
percentage_change = tsdeltap(gdp, lag=1)

# Equivalent method form
same_lagged = gdp.lag(1)
same_led = gdp.lead(1)
same_difference = gdp.delta(lag=1)
same_log_difference = gdp.delta_log(lag=1)
percentage_change = gdp.delta_percent(lag=1)
```

Percentage changes for an intra-annual series can be annualized:

```python
annualized = tsdeltap(gdp, lag=1, annualize=True)
same_annualized = gdp.delta_percent(lag=1, annualize=True)
```

## Functional and method APIs

The functional API preserves names familiar to BIMETS users; methods support
object-oriented code and operation chaining. The following pairs are
equivalent:

| Function form | Method form |
|---|---|
| `get_dates(series, ...)` | `series.dates(...)` |
| `tslag(series, periods)` | `series.lag(periods)` |
| `tslead(series, periods)` | `series.lead(periods)` |
| `tsdelta(series, lag, order)` | `series.delta(lag, order)` |
| `tsdeltalog(series, lag)` | `series.delta_log(lag)` |
| `tsdeltap(series, lag, ...)` | `series.delta_percent(lag, ...)` |
| `tsproject(series, start, end, ...)` | `series.project(start, end, ...)` |
| `tstrim(series, ...)` | `series.trim(...)` |
| `cumsum(series, ...)` | `series.cumulative_sum(...)` |
| `cumprod(series, ...)` | `series.cumulative_product(...)` |
| `movavg(series, window, ...)` | `series.moving_average(window, ...)` |
| `movtot(series, window, ...)` | `series.moving_sum(window, ...)` |
| `indexnum(series, base_year)` | `series.index_number(base_year)` |
| `tsextend(series, ...)` | `series.extend(...)` |
| `convert_frequency(series, freq, ...)` | `series.to_frequency(freq, ...)` |
| `annual(series, ...)` | `series.to_frequency("Y", ...)` |
| `semiannual(series, ...)` | `series.to_frequency("S", ...)` |
| `quarterly(series, ...)` | `series.to_frequency("Q", ...)` |
| `monthly(series, ...)` | `series.to_frequency("M", ...)` |
| `daily(series, ...)` | `series.to_frequency("D", ...)` |

Operations involving multiple series, such as `tsmerge()` and `tsjoin()`,
remain functions because no single input series is the natural receiver.

### Naming conventions and R compatibility aliases

Canonical Python names use lowercase `snake_case`. Compatible BIMETS R names
are exported as exact case-sensitive aliases; the complete mapping is in the
[API inventory](../reference/api.md). Examples include `CSV2BIMETS`, `TSLOOK`,
`STOCHSIMULATE`, `RENORM`, `date2yp`, and `normalizeYP`. Intermediate spellings
such as `csv2bimets` and `stochsimulate` are deliberately omitted; use the
canonical Python name or the exact R name.

All R aliases reference the same callable and do not have separate behavior.
Compatibility aliases keep Python keyword names and return types. Names such as
`tslag`, `tsdelta`, and `movtot` remain the canonical functional API; their
method forms are listed above.

## Aggregation and disaggregation

`convert_frequency()` converts yearly, semiannual, quarterly, monthly, and
daily series. Convenience functions are available for each target frequency:

```python
from bimets import annual, daily, monthly, quarterly, semiannual

yearly_gdp = annual(gdp, method="average")
monthly_gdp = monthly(gdp)  # repeat each quarterly observation
daily_gdp = daily(gdp, method="interp_center")

# Equivalent method form
same_yearly_gdp = gdp.to_frequency("Y", method="average")
same_monthly_gdp = gdp.to_frequency("M")
same_daily_gdp = gdp.to_frequency("D", method="interp_center")
```

Aggregation requires one of the following methods:

- `"stock"`: last observation in the target period;
- `"nstock"`: last non-missing observation;
- `"sum"` and `"average"`: propagate missing values;
- `"nsum"` and `"naverage"`: ignore missing values.

Disaggregation repeats each source value by default. Linear interpolation can
instead align source observations with the beginning, center, or end of their
periods by using `"interp_begin"`, `"interp_center"`, or `"interp_end"`.

Any target frequency can also be selected directly with the method form:

```python
quarterly_gdp = monthly_gdp.to_frequency("Q", method="average")
```

## Projection and trimming

`tsproject()` selects an inclusive range. With `extend=True`, portions outside
the source range are filled with missing values (`NaN`):

```python
from bimets import tsproject, tstrim

selection = tsproject(gdp, (2020, 2), (2020, 4))
extended = tsproject(gdp, (2019, 4), (2020, 2), extend=True)

without_missing_edges = tstrim(extended)

# Equivalent method form
same_selection = gdp.project((2020, 2), (2020, 4))
same_extended = gdp.project((2019, 4), (2020, 2), extend=True)
same_without_missing_edges = extended.trim()
```

`tstrim()` returns `None` when no observations remain.

## Cumulative and moving-window operations

```python
from bimets import cumprod, cumsum, movavg, movtot

series = timeseries([1, 2, 3, 4, 5], start=(2020, 1), freq="M")

cumulative_sum = cumsum(series)
cumulative_product = cumprod(series)
cumulative_sample = cumsum(series, start=(2020, 2), end=(2020, 4))
moving_average = movavg(series, window=3)
moving_total = movtot(series, window=3)

# Equivalent method form
same_cumulative_sum = series.cumulative_sum()
same_cumulative_product = series.cumulative_product()
same_cumulative_sample = series.cumulative_sum(
    start=(2020, 2), end=(2020, 4)
)
same_moving_average = series.moving_average(window=3)
same_moving_total = series.moving_sum(window=3)
```

Cumulative operations accept `skip_missing=True` and optional inclusive
`start`/`end` bounds corresponding to BIMETS R `TSRANGE`. `cumsum()` can also
reset the cumulative value when the year or month changes:

```python
yearly_cumulative = cumsum(series, mode="yearly")
monthly_cumulative = cumsum(series, mode="monthly")

same_yearly_cumulative = series.cumulative_sum(mode="yearly")
same_monthly_cumulative = series.cumulative_sum(mode="monthly")
```

Moving windows support three alignments: `"back"` (the default), `"center"`,
and `"ahead"`. These operations also accept `skip_missing=True`.

## Rebasing

`indexnum()` rebases a series to 100 in the selected year. For frequencies
greater than one, it uses the average of the observations in the base year:

```python
from bimets import indexnum

index = indexnum(gdp, base_year=2020)
same_index = gdp.index_number(base_year=2020)
```

The base year must fall within the series, must not contain missing values, and
must not have an average of zero.

## Merge and join

`tsmerge()` combines series of the same frequency over the union of their
ranges. Without an aggregation function, the first non-missing observation is
selected for each period according to argument order:

```python
from bimets import tsmerge

first = timeseries([1, 2, 3], start=(2020, 1), freq="Q")
second = timeseries([10, 20, 30], start=(2020, 3), freq="Q")

prioritized = tsmerge(first, second)
total = tsmerge(first, second, method="sum")
average = tsmerge(first, second, method="average")
maximum = tsmerge(first, second, method="max")
minimum = tsmerge(first, second, method="min")
```

With the default `skip_missing=True`, missing or uncovered inputs are ignored
during aggregation. Setting `skip_missing=False` propagates them instead.

`tsjoin()` uses the first series before the join period and the second series
from that period onward:

```python
from bimets import tsjoin

joined = tsjoin(first, second)
joined_at_period = tsjoin(first, second, join_period=(2020, 4))
```

If there is a gap between the series, `allow_gap=True` fills it with missing
values.

## Named datasets

`BimetsDataset` is an immutable, ordered mapping of names to
`BimetsSeries` objects. It provides an explicit representation for the named
collections commonly passed between BIMETS operations:

```python
from bimets import BimetsDataset

cpi = timeseries([98, 99, 101, 102], start=(2020, 1), freq="Q")
economy = BimetsDataset(
    {"gdp": gdp, "cpi": cpi},
    metadata={"source": "Example database"},
)

economy.names
economy["gdp"]
prices = economy.select(["cpi"])
renamed = economy.rename({"cpi": "prices"})
changes = economy.map(lambda series: series.delta_percent())
```

`select()`, `drop()`, `rename()`, `with_series()`, and `combine()` return new
datasets. `range()` reports the inner or outer range of a homogeneous-frequency
dataset, while `align()` projects all selected variables onto that range:

```python
common_sample = economy.align(kind="inner")
complete_sample = economy.align(kind="outer")  # fills uncovered periods with NaN
frame = economy.to_frame()
restored = BimetsDataset.from_frame(frame)
```

Mixed-frequency datasets are supported as collections, but range alignment
and conversion to one DataFrame require a common frequency. `to_pandas()`
instead returns one pandas Series per variable and therefore also supports
mixed frequencies. `BimetsDataset.to_csv()` and `BimetsDataset.from_csv()`
provide dataset-oriented access to the CSV exchange functions.

`to_frame()` aligns columns on the outer dataset range and stores the common
frequency and dataset-level metadata in `DataFrame.attrs`. `from_frame()`
accepts a regular pandas `PeriodIndex`, `DatetimeIndex`, or BIMETS year-period
`MultiIndex`; a frame produced by `to_frame()` therefore round-trips without
requiring an explicit frequency.

Use `assign_range()` to build a model scenario without mutating the baseline:

```python
policy_scenario = economy.assign_range(
    {
        "gdp": [108.0, 110.0],
        "cpi": 103.0,  # scalars are broadcast
    },
    start=(2020, 3),
    end=(2020, 4),
)
```

The bounds are inclusive and sequences must have exactly one value per period.
By default they must lie inside every affected series. Pass `extend=True` to
expand an affected series and fill uncovered observations with `numpy.nan`.
Unaffected variables are shared safely because series and datasets are
immutable.

## Extending a series

`tsextend()` expands a series range backward, forward, or in both directions:

```python
from bimets import tsextend

extended = tsextend(
    gdp,
    back_to=(2019, 1),
    up_to=(2022, 4),
    mode="growth",
)

# Equivalent method form
same_extended = gdp.extend(
    back_to=(2019, 1),
    up_to=(2022, 4),
    mode="growth",
)
```

The following modes are available:

| Mode | Behavior |
|---|---|
| `"missing"` | inserts missing values |
| `"zero"` | inserts zeroes |
| `"constant"` | repeats the nearest valid value |
| `"mean4"` | uses the mean of four observations |
| `"growth"` | continues the nearest available growth rate |
| `"growth4"` | estimates growth from two groups of four observations |
| `"linear"` | applies a linear extension |
| `"quadratic"` | applies a quadratic extension |
| `"myconst"` | uses `factor` as the extension value |
| `"myrate"` | uses `factor` as the growth factor |

Examples with a user-supplied parameter:

```python
constant = tsextend(gdp, up_to=(2022, 4), mode="myconst", factor=100)
growth = tsextend(gdp, up_to=(2022, 4), mode="myrate", factor=1.02)

same_constant = gdp.extend(up_to=(2022, 4), mode="myconst", factor=100)
same_growth = gdp.extend(up_to=(2022, 4), mode="myrate", factor=1.02)
```

## Pandas conversion

`to_pandas()` converts a `BimetsSeries` to a `pandas.Series` while preserving
its metadata. The year-period representation is available for every
frequency:

```python
from bimets import from_pandas, to_pandas

table = to_pandas(gdp)                         # year-period MultiIndex
periods = to_pandas(gdp, index="period")       # PeriodIndex
dates = to_pandas(gdp, index="datetime")       # DatetimeIndex

restored = from_pandas(table)
```

`PeriodIndex` and `DatetimeIndex` are available for yearly, quarterly, and
monthly series. All other frequencies use a `MultiIndex` with `year` and
`period` levels.

## Inspection and tabular presentation

Printing a series follows the frequency-dependent layout of R `ts`. Quarterly
and monthly observations are arranged as year-by-cycle matrices. Annual,
semiannual, three-period, high-frequency, weekly, and daily series use a
compact `Time Series` block containing their range, frequency, values, and
metadata. `repr(series)` is a separate Python-oriented technical view with an
abbreviated value preview, range, frequency, and metadata.

```python
print(gdp)
#      Qtr1 Qtr2 Qtr3 Qtr4
# 2020  100  102  105  107
```

```python
from bimets import get_range, get_year_periods, series_info, tabulate, tsinfo

info = series_info(gdp)
common_range = get_range(gdp, quarterly_gdp, kind="inner")
table = tabulate(gdp, quarterly_gdp, headers=["GDP", "Quarterly GDP"])

typed_periods = get_year_periods(gdp)
named_periods = get_year_periods(gdp, years="YEAR", periods="PRD")
period_matrix = get_year_periods(gdp, join=True)

start = tsinfo(gdp, mode="start")       # YearPeriod
r_start = tsinfo(gdp, mode="START")    # fractional year, as in R
titles = tsinfo(gdp, quarterly_gdp, mode="TITLE")
```

`series_info()` returns a `SeriesInfo` value containing the range, frequency,
and standard metadata. `get_range()` supports `kind="inner"` for intersection
and `kind="outer"` for union. `tabulate()` aligns the input series and returns
a pandas `DataFrame` with frequency-aware `Date`/`Prd.` labels generated by the
same display formatter. The uppercase `TABIT` alias returns the same table;
unlike R, it does not print as a side effect.

`get_year_periods()` returns typed `YearPeriod` objects by default. Its named
and joined forms cover the `YEARS`, `PERIODS`, and `JOIN` outputs of
`GETYEARPERIOD`. `tsinfo()` accepts one or more series and every BIMETS R mode.
With one series it returns a scalar; with multiple series it returns a tuple.
Lowercase `start`/`end` are the typed Python forms, while uppercase
`START`/`END` reproduce the fractional-year R result.

`magnitude()` computes the Euclidean magnitude of a series while ignoring
missing observations. `verify_magnitude()` finds the series in a collection
whose magnitude exceeds a selected threshold.

## CSV exchange

`bimets_to_csv()` and `csv_to_bimets()` preserve names, frequencies,
year-period ranges, values, and missing observations:

```python
from bimets import bimets_to_csv, csv_to_bimets

bimets_to_csv({"gdp": gdp}, "series.csv", overwrite=True)
restored = csv_to_bimets("series.csv")
restored_gdp = restored["gdp"]
```

The default paired layout supports series with different frequencies and
ranges. Set `merged=True` to produce a single shared date column; all series
must then have the same frequency. By default, files use a BIMETS-compatible
`sep=,` delimiter metadata and `YYYY/MM/DD` dates. Both import and export
support a custom delimiter, decimal separator, missing-value marker, and date
format. On import, a leading `sep=` line overrides the `delimiter` argument.

The frequency header is optional on import. As in BIMETS R, frequency is then
inferred from the minimum positive spacing between dates, and missing periods
inside the resulting regular range are filled with `NaN`. Duplicate dates,
different dates falling in the same BIMETS period, and decreasing periods are
rejected rather than silently compressed.

Use `skip_lines=` for title or preamble rows after the optional `sep=` line,
and `freq_header_prefix=` to read or write a prefix other than `FREQ_`:

```python
bimets_to_csv(
    {"gdp": gdp},
    "series.csv",
    overwrite=True,
    freq_header_prefix="PERIODS_",
)
restored = csv_to_bimets(
    "series.csv",
    freq_header_prefix="PERIODS_",
)
```

Export also supports the substantial BIMETS R options in Python form:

```python
bimets_to_csv(
    [gdp],
    "plain-table.csv",
    overwrite=True,
    time_range=(2020, 2, 2020, 4),
    name_metadata_key="title",
    title_lines="Quarterly national accounts",
    plain_table=True,
)
```

`time_range` corresponds to `TSRANGE`, `name_metadata_key` to
`attributeOfNames`, `title_lines` to `title`, and `plain_table` to
`plainTable`. `append=True` appends another complete table. Quarter-based date
formats such as `date_format="%Y Q%q"` work in both directions.

Frequency conversion preserves descriptive metadata. Arithmetic and
mathematical transformations intentionally do not inherit it, because fields
such as units or scale may no longer describe the derived values correctly.
