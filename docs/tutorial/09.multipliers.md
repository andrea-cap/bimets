# Multiplier matrices

[Back to the tutorial index](README.md)

`multiplier_matrix()` computes the response of selected endogenous targets to
a one-period shock in one or more instruments. It corresponds to
`MULTMATRIX()` in BIMETS R, which is exported as an exact compatibility alias.
The operation is also available as `model.multiplier_matrix()` and
`bound_model.multiplier_matrix()`.

The following backward-looking model makes the distinction between the two
supported matrices explicit:

```python
from bimets import BimetsModel, multiplier_matrix, timeseries

multiplier_model = BimetsModel.from_text(
    """MODEL
IDENTITY> y
EQ> y = x + 0.5 * TSLAG(y)
END""",
    name="multiplier-example",
)
multiplier_data = {
    "y": timeseries([0, 0, 0], start=(2000, 1)),
    "x": timeseries([1, 1, 1], start=(2000, 1)),
}

interim = multiplier_matrix(
    multiplier_model,
    multiplier_data,
    coefficients={},
    time_range=(2001, 1, 2002, 1),
    targets="y",
    instruments="x",
)
interim.matrix.round(6).tolist()
# [[1.0, 0.0], [0.5, 1.0]]

# Equivalent method forms
same_interim = multiplier_model.multiplier_matrix(
    multiplier_data,
    coefficients={},
    time_range=(2001, 1, 2002, 1),
    targets="y",
    instruments="x",
)
bound_interim = multiplier_model.bind(multiplier_data).multiplier_matrix(
    coefficients={},
    time_range=(2001, 1, 2002, 1),
    targets="y",
    instruments="x",
)

impact = multiplier_model.multiplier_matrix(
    multiplier_data,
    coefficients={},
    time_range=(2001, 1, 2002, 1),
    targets="y",
    instruments="x",
    simulation_type="STATIC",
)
impact.matrix.round(6).tolist()
# [[1.0, 0.0], [0.0, 1.0]]
```

`DYNAMIC` produces interim multipliers, so an impulse can propagate to later
periods through lags. `STATIC` produces impact multipliers and resets lagged
endogenous values to observed data at each period. In a forward-looking model,
dynamic multipliers can also contain anticipation effects before the impulse.
`FORECAST` uses forecast initialization and is available both directly and
through `RENORM`.

All instrument-period shocks are assembled as columns of one matrix.
Gauss-Seidel uses a shared convergence stop; `NEWTON` reuses the baseline
sparse Jacobian and solves every column update as multiple right-hand sides.
This includes lead systems and reduced `jacobian_drop` systems. Only
`FULLNEWTON` retains an independent solver per column.

Rows are ordered by period and then target; columns are ordered by period and
then instrument. `result.summary()` returns the same values as a labeled pandas
`DataFrame`, while `result.at("y", 2, "x", 1)` selects one value using one-based
period positions, consistent with the labels. The numerical matrix itself is
available as a read-only NumPy array in `result.matrix`.

Exogenous instruments are shocked directly. An endogenous instrument instead
shocks its equation constant adjustment (the BIMETS add-factor), and its column
label therefore contains `ADDFACTOR`. As in BIMETS R, the actual increment is
`baseline * shock` when the baseline instrument is at least one and is the
absolute `shock` otherwise; the default is `1e-5`.

Multiplier values divide simulation differences by a small impulse, so the
deterministic solver tolerance should be tighter than the impulse when close
numerical agreement is required. For example, the original Klein multiplier
example is reproduced with `convergence=1e-8`.

`algorithm="FULLNEWTON"` gives the baseline and every shocked simulation an
independent Jacobian. Set `workers` above one to distribute these independent
shock solves across processes; the option is deliberately unavailable for the
faster shared Gauss-Seidel and ordinary-Newton paths. `backfill` prepends
historical values to the stored
baseline, but matrix rows and columns still cover only `time_range`.
`jacobian_drop` is applied consistently to the baseline and all shocks.

See the [multiplier matrix API](../reference/multipliers.md) for complete
signatures and result attributes.
