# Deterministic simulation

[Back to the tutorial index](README.md)

An estimated model can be simulated either with `simulate()` or through the
equivalent model methods. Coefficients are passed explicitly: they may be an
immutable `ModelEstimationResult` returned by `estimate()`, or a nested mapping
for calibrated models.

The following example reuses `consumption_model` and `klein_data` from the
[estimation guide](06.estimation.md):

```python
from bimets import simulate

coefficients = consumption_model.estimate(klein_data)

simulation = simulate(
    consumption_model,
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    simulation_type="DYNAMIC",
    convergence=0.00001,
)

# Equivalent object-oriented forms
same_simulation = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    convergence=0.00001,
)
bound_simulation = consumption_model.bind(klein_data).simulate(
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    convergence=0.00001,
)

simulation["cn"]          # simulated BimetsSeries
simulation.summary()       # all endogenous variables as a DataFrame
simulation.iterations      # read-only per-period iteration counts
simulation.blocks          # ordered recursive/simultaneous equation blocks
```

The deterministic simulator supports four BIMETS simulation types:

| Type | Treatment of endogenous variables |
|---|---|
| `DYNAMIC` | Current-period equations use simulated current values and simulated endogenous lags. |
| `STATIC` | Current-period equations are solved together, while endogenous lags retain their observed values. |
| `FORECAST` | Like a dynamic simulation; an available current endogenous observation initializes iteration, while a missing value falls back to the previous simulated period. |
| `RESCHECK` | Each equation is evaluated against observed inputs without simultaneous iteration; the result also contains the tracking adjustments required to reproduce observed values. |

Backward-looking models are split into topologically ordered recursive and
simultaneous blocks. Simultaneous blocks are solved period by period with
Gauss-Seidel or a sparse finite-difference Newton solver. Within each cyclic
component, BIMETS incidence reduction orders recursive equations around a
small feedback set. Inspect `block.variables` for the evaluation order and
`block.feedback` for the variables used by the Gauss-Seidel convergence test.
This reduction is built once per simulation, outside period and iteration
loops. Conditional identities, PDL regressors, autoregressive errors declared
with `ERROR> AUTO(n)`, and
`LOG`, `EXP`, `TSDELTA`, `TSDELTALOG`, and `TSDELTAP` left-hand-side
transformations are supported.

```python
newton_simulation = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    algorithm="NEWTON",
    jacobian_step=1e-4,
)
```

Newton Jacobians are stored in SciPy compressed sparse-column form and solved
through sparse LU factorization. The structural dependencies obtained from the
MDL equations are used to perturb independent columns together, so a sparse
model generally requires far fewer residual evaluations than one perturbation
per unknown. The same backend is used for the extended multi-period system of
forward-looking models. Jacobians are reused while convergence is satisfactory;
slow convergence causes relaxation or reconstruction, following the strategy
used internally by BIMETS R.

As in BIMETS R, `FULLNEWTON` is not valid for a single deterministic
`simulate()` call. It is available through stochastic simulation, multiplier
matrices, renormalization, and optimization, where it builds an independent
Jacobian for every realization or shocked solution.

Use `backfill` to include available historical observations before the
simulation range in the returned series:

```python
with_history = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    backfill=2,
)
```

This changes only the returned series range. Equations, convergence checks,
and `result.iterations` remain restricted to `time_range`.

## Conditional identities

`IF>` conditions are evaluated during simulation and again at every solver
iteration. All conditional alternatives remain part of the structural
dependency graph, even if a condition happens to be always false in one run.

When no alternative for an endogenous identity is true in a period, BIMETS
keeps the value supplied for that variable in the model data. Conditional
endogenous variables therefore require a finite historical value throughout
the simulation range, including a `FORECAST` range. They are not automatically
reclassified as exogenous and remain eligible for feedback and Jacobian
analysis.

For example, when `cond <= 0`, `Y` keeps its supplied path while `Z` is solved:

```text
IDENTITY> Y
EQ> Y=Z
IF> cond>0

IDENTITY> Z
EQ> Z=Y+1
IF> cond<=0
```

An inactive feedback identity can make a Newton Jacobian singular because its
current value is left unchanged. This is the intended BIMETS R behavior; use
`jacobian_drop` for that variable when appropriate.

If a feedback equation contains a discontinuity or an unverified conditional,
exclude its variable from the numerical Jacobian while retaining it in the
simulation:

```python
hybrid = model.simulate(
    data,
    coefficients=coefficients,
    time_range=(2000, 1, 2005, 1),
    algorithm="NEWTON",
    jacobian_drop="profits",
)
```

Dropped variables continue to be updated by Gauss-Seidel, while Newton solves
the remaining feedback variables. Backward-looking convergence is checked on
the reduced feedback set. A name that is not a feedback variable is ignored
with `UserWarning`, following BIMETS R's behavior. If dropping or exogenizing
variables leaves no active Newton variable, another `UserWarning` reports that
the block falls back to Gauss-Seidel. The option also applies to extended
forward-looking systems and is forwarded by all advanced simulation APIs.

When coefficients come from `estimate()`, autoregressive coefficients are
carried into simulation automatically. A calibrated nested mapping must use
the names `RHO_1`, `RHO_2`, and so on. Set
`zero_error_autocorrelation=True` to reproduce the `ZeroErrorAC=TRUE`
behavior of BIMETS R.

Scalar or time-varying constant adjustments are added on the transformed
equation scale. Endogenous variables can be exogenized over the full range,
over a selected range at their observed values, or over the range of an
explicit replacement series:

```python
adjusted = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    constant_adjustments={"cn": 0.5},
)

fixed = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    exogenize=("cn",),
)

partially_fixed = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    exogenize={"cn": (1930, 1, 1935, 1)},
)

residual_check = consumption_model.simulate(
    klein_data,
    coefficients=coefficients,
    time_range=(1923, 1, 1941, 1),
    simulation_type="RESCHECK",
    rescheck_equations="cn",
)
tracking_adjustments = residual_check.constant_adjustments
```

## Forward-looking and rational-expectations models

A model is forward-looking when at least one equation contains `TSLEAD`.
As in BIMETS R, all endogenous variables and all periods in the requested
range are then solved as one extended system. Historical observations before
the range provide initial conditions, while observations after the range
provide terminal expectations.

```python
from bimets import BimetsModel, timeseries

rational_model = BimetsModel.from_text(
    """MODEL
IDENTITY> y
EQ> y = 0.5*TSLEAD(y) + 0.2*TSLAG(y) + x
END""",
    name="rational-expectations",
)

rational_data = {
    # 2000 is the initial boundary and 2003 the terminal boundary.
    "y": timeseries([1, 10, 20, 4], start=(2000, 1)),
    "x": timeseries([0, 2, 3, 0], start=(2000, 1)),
}

rational_result = rational_model.simulate(
    rational_data,
    coefficients={},
    time_range=(2001, 1, 2002, 1),
    algorithm="NEWTON",
)
rational_result["y"].values.tolist()
# [5.222222222222222, 6.044444444444444]
```

Only `DYNAMIC` and `RESCHECK` are meaningful for a forward-looking model,
matching the restriction in BIMETS R. Gauss-Seidel and Newton are both
available. Exogenization and constant adjustments operate at their actual
periods within the extended system.

The implementation is also validated against the rational-expectations Klein
example distributed with BIMETS. Its investment identity is:

```text
IDENTITY> i
EQ> i = (MOVAVG(i,2)+TSLEAD(i))/2
```

With the published terminal expectation `i[1931] = 2`, simulation over
1924--1930 reproduces the original investment values:

```text
3.594946, 2.792062, 2.390277, 2.189125,
2.088380, 2.037915, 2.012644
```

Python evaluates `TSLEAD` directly over the shared multi-period working data.
It therefore does not expose the generated `variable__LEAD__n` names used
internally by the R implementation. A forward-looking `SimulationResult`
reports one global simultaneous block and the common iteration count for each
period. The extended Jacobian remains sparse across variables and periods;
lead and lag relationships normally form narrow off-diagonal bands rather than
a dense matrix.

See the [deterministic simulation API](../reference/simulation.md) for exact
signatures and [Solver architecture and execution
strategies](../explanation/solver-strategies.md) for the scalar, sparse, and
forward-looking solution paths.
