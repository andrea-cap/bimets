# Monte Carlo optimal control

[Back to the tutorial index](README.md)

`optimize_model()` implements the Monte Carlo optimal-control procedure of
BIMETS R `OPTIMIZE()`, which is also exported as an exact alias. The method
forms are `model.optimize()` and `bound_model.optimize()`.

Unlike `renormalize()`, optimal control does not require a desired path for
each target. It samples policy instruments uniformly inside user bounds,
simulates every candidate path, discards candidates that violate restrictions
or produce a non-finite objective, and selects the realization with the
largest summed objective value.

```python
from bimets import BimetsModel, optimize_model, timeseries

control_model = BimetsModel.from_text(
    """MODEL
IDENTITY> y
EQ> y = 2 * x
END""",
    name="optimal-control-example",
)
control_data = {
    "y": timeseries([0], start=(2000, 1)),
    "x": timeseries([0], start=(2000, 1)),
}

control_result = optimize_model(
    control_model,
    control_data,
    coefficients={},
    time_range=(2000, 1, 2000, 1),
    bounds={"x": (0, 5)},
    objective_functions="y",
    restrictions="x <= 4",
    replicas=1_000,
    seed=123,
    simulation_type="STATIC",
)
control_result.objective_max
control_result.instruments["x"]
control_result.feasible_count
control_result.summary()

# Equivalent method forms
same_control = control_model.optimize(
    control_data,
    coefficients={},
    time_range=(2000, 1, 2000, 1),
    bounds={"x": (0, 5)},
    objective_functions="y",
    restrictions="x <= 4",
    replicas=1_000,
    seed=123,
    simulation_type="STATIC",
)
bound_control = control_model.bind(control_data).optimize(
    coefficients={},
    time_range=(2000, 1, 2000, 1),
    bounds={"x": (0, 5)},
    objective_functions="y",
    restrictions="x <= 4",
    replicas=1_000,
    seed=123,
    simulation_type="STATIC",
)
```

Tuple bounds apply over the complete optimization range. Dedicated definitions
support different non-overlapping periods:

```python
from bimets import OptimizationBound, OptimizationFunction

bounded_policy = {
    "x": OptimizationBound(0, 5, time_range=(2001, 1, 2002, 1)),
}
dated_objectives = {
    "initial": OptimizationFunction("y", (2000, 1, 2000, 1)),
    "policy": OptimizationFunction("2*y-x", (2001, 1, 2002, 1)),
}
```

`OptimizationRestriction` provides the corresponding time-ranged form for a
restriction. Expressions use the safe MDL parser and can contain arithmetic,
logical operators, lags, leads, moving functions, `ABS`, `LOG`, and `EXP`.

As in BIMETS R, an endogenous name in `bounds` identifies its equation
add-factor. Endogenous names have deliberately different meanings in the two
expression contexts:

- objective functions read simulated endogenous values;
- restrictions read endogenous add-factors, while exogenous names read their
  sampled values.

`OptimizationResult` exposes the maximizing instruments and adjusted inputs,
the selected objective path, `objective_max`, mean and sample standard
deviation, the unfiltered `objective_results`, the `feasible` mask, and the
complete stochastic simulation. BIMETS-compatible property aliases
`opt_fun_max`, `opt_fun_ave`, and `opt_fun_sd` are also available. If no finite
candidate satisfies the restrictions, optimum fields are `None` while all
realization diagnostics remain available.

The original advanced Klein example is represented directly by:

```python
klein_control = optimize_model(
    advanced_klein_model,
    advanced_klein_data,
    coefficients=advanced_klein_estimation,
    time_range=(1942, 1, 1942, 1),
    simulation_type="FORECAST",
    bounds={"cn": (-5, 5), "g": (15, 25)},
    restrictions="g+(cn^2)/2 < 27 & g+cn > 17",
    objective_functions="(y-110)+(cn-90)*ABS(cn-90)-(g-20)^0.5",
    replicas=10_000,
    seed=123,
)
```

Here `cn` in `bounds` and `restrictions` is the consumption-equation
add-factor, whereas `cn` in the objective is simulated consumption. An explicit
seed reproduces R's default Mersenne Twister candidate paths, including R's
column-major matrix-filling order.

Gauss-Seidel and common-Jacobian `NEWTON` evaluate the baseline and candidate
paths as columns of shared NumPy matrices.
One convergence check covers the complete matrix, as in BIMETS R; Newton also
reuses the baseline sparse factorization and solves every candidate right-hand
side together. Common exogenization and `RESCHECK` remain on this vectorized
path. The layout is normally faster than distributing individual candidates
to worker processes because it avoids serialization and process-management
costs while the numerical kernels run in compiled NumPy code. This shared path
also covers forward-looking and reduced-`jacobian_drop` systems. Only
`FULLNEWTON` retains independent candidate solves.

If a shared Gauss-Seidel or Newton solve reaches `max_iterations`, the final
iteration is retained and a `RuntimeWarning` identifies the period, block,
largest change, and candidate column. This reproduces BIMETS R's optimization
behavior and allows the search to continue with explicit diagnostics.

For strongly nonlinear candidate paths, `algorithm="FULLNEWTON"` builds a
separate Jacobian for every candidate. These independent candidate solves may
use `workers` processes; ordinary `NEWTON` remains single-process because its
shared factorization and multi-right-hand-side solve are more efficient.
`backfill` extends only deterministic baselines stored in the stochastic
result; objective paths retain `time_range`. `jacobian_drop` applies the same
reduced-Newton structure to all candidate simulations.

signatures, definition types, result attributes, and failures.
